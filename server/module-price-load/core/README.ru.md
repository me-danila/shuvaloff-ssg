### Настройки выгрузки цен <a name="settings"></a>

Настройки модуля указываются в трёх файлах.

Список отелей задаётся в файле `module-price-load/core/settings/common/hotels.json`.
* `hotels`: _array\<integer\>_, **required** - отели, для которых необходимо выгрузить цены

Основные настройки модуля задаются в файле `module-price-load/core/settings/common/basic.json`.

* `days`: _integer_, **required** - глубина поиска цен в днях (максимум: 100)
* `currencies`: _array\<string\>_, **required** - валюты выгружаемых цен
* `minLosLimit`: _integer_, **required** - глубина проверяемых minLos (минимальный период бронирования). Если установить, например, `5`, то будут проверены все периоды бронирования от 1 до 5: 1 день, 2 дня, 3 дня, 4 дня и 5 дней в течение того количества дней, которое указано выше.  
Можно отключить ограничение на глубину, указав `0`. В этом случае, будут проверяться все возможные minLos, заданные отелем в тарифах.
* `startTomorrow`: _boolean_ - начать поиск цен, начиная с завтрашнего дня. По умолчанию поиск цены работает с сегодняшнего дня.
* `enableCache`: _boolean_ - включает/отключает кэширование цен. По умолчанию цены кэшируются. Т.е. в случае, когда номер забронирован и цена не была выгружена, сохраняется предыдущая выгруженная цена.

Дополнительные настройки модуля задаются в файле `module-price-load/core/settings/common/extra.json`.
* `languages`: _array\<string\>_ - языки, на которых нужно выгрузить названия тарифов в формате `ru`, `en`. По умолчанию задан русский язык, но если он не задан у отеля, то выгрузит на языке отеля.
* `requireOffers`: _array\<integer\>_ - ограничение выгрузки цен только по указанным id тарифов. Указать по желанию.
* `pricesAvailableFromDate`: _string_ - дата в формате `yyyy-mm-dd`, с которой номера доступны для бронирования. Задаётся в случае, когда на ближайшие несколько месяцев всё забронировано. Т.о. на эти месяцы нельзя выгрузить цены для номеров. Чтобы автовыгрузка начала работать прямо сейчас, а не через несколько месяцев, нужно установить дату, с которой доступно бронирование. Когда реальная дата пересечет указанную, автовыгрузка продолжит работать в штатном режиме. Для всех отелей устанавливается одна дата.

### Режим вывода процесса работы в консоль <a name="console-mode"></a>

В модуле предусмотрен режим вывода этапов работы модуля в консоль, параметр `MODULE_PRICE_LOAD_CONSOLE_LOG_MODE` в файле `module-price-load/core/configs/common/core.php`.

Этот режим позволяет отображать процесс выгрузки цен в консоли: последовательный вывод выгружаемых отелей, валют, названий API и количество запросов к ним.

### Режим дебага <a name="debug-mode"></a>

В модуле предусмотрен режим дебага, параметр `MODULE_PRICE_LOAD_DEBUG_MODE` в файле `module-price-load/core/configs/common/core.php`.

В этом режиме модуль сохраняет некоторые выгруженные данные по отелям, запросы к API и результаты запросов к API в файлы.

В режиме дебага файл с ценами не проверяется на преждевременное обновление данных и перезаписывается каждый раз при запуске модуля. Это означает, что при каждом запуске модуля будут отправляться запросы к API. Эти действия могут сильно нагрузить API, поэтому будьте осторожны.

Пользоваться этим режимом необходимо очень аккуратно. Желательно запускать его **_только для одного отеля_**, т.к. файлов логов генерируется очень много.

Логи сохраняются в директорию `module-price-load/core/logs/`.

Директории с логами генерируются автоматически. Необходимы права на создание и удаление директорий.

### Файл с ценами <a name="prices"></a>

Цены сохраняются в файл `module-price-load/cache/price.json`. Файл создаётся автоматически. Если файл не обновляется, проверьте файл логов. Скорее всего Вы пытаетесь преждевременно обновить файл с ценами. Если есть необходимость в преждевременном обновлении, удалите файл с ценами. При следующем запуске модуля он создастся автоматически.

Не нужно заранее создавать файл вручную. Модуль проверяет время обновления файла.

### Статус завершения работы (логи) <a name="log"></a>

Статус выполнения работы скрипта записывается в файл `module-price-load/core/logs/log.txt`. 

Если работа выполнена успешно, лог перезаписывается и оставляет только дату и время последнего выполнения.

Если возникла ошибка, то лог обновится и добавит в файл информацию об ошибке. Каждая следующая ошибка будет добавляться в файл лога.
